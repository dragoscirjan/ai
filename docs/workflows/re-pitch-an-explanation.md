# Ask for a clearer explanation

The last proposal or explanation is unclear, lacks context, or does not use the project's shared vocabulary.

**Finish with:** A re-pitched explanation grounded in the missing context and existing project terminology.

Arrows show this suggested sequence, not declared `requires` dependencies. Approval arrows are conditional. Declining a gate stops that branch without authorizing its writes. The numbered steps below are the text equivalent of the diagram.

## Before you start

Use a trusted project and follow its instructions. Confirm the requested scope, installed skills, runtime tools, and any required workspace or approval. No additional instruction requirement is recorded for these selected steps.

## Steps

1. **Name the unclear answer.** [`wait-what`](/skills/wait-what) provides the guidance for this step.
2. **Check glossary and context.** [`wait-what`](/skills/wait-what) provides the guidance for this step.
3. **Use precise language.** [`asd-ste100-technical`](/skills/asd-ste100-technical) provides the guidance for this step.
4. **Re-pitch; check meaning.** [`wait-what`](/skills/wait-what) provides the guidance for this step.

## Where to stop

This is an explicit clarification request, not an adversarial critique or a change request. Resolve project vocabulary through GLOSSARY.md and GLOSSARY-MAP.md as applicable; ask about missing inputs rather than inventing or creating a glossary. Stop after the explanation.

## Optional branches

- Choose [`unslop`](/skills/unslop) when a draft contains generic phrasing, repetitive structure, filler, or claims that do not help the reader act.

Optional branches are not prerequisites or permission to launch another phase. You can omit them or stop at the stated result. See [relationship types](/reference/relationships) for the distinction.
